# HTTP and Webhook Workbench

Install, explicitly trust the author, configure `endpoint` as literal `127.0.0.1:port`, then explicitly enable. Nothing auto-enables. The default tool permission is **Ask**. This sends requests to a local developer service; it does not create a public webhook listener.

Even a loopback call can modify or delete data. `replay:true` executes the approved method a second time; do not use it on non-idempotent operations unless duplication is intended. There are no automatic retries, schedules or saved recordings. A response refusal or timeout does not undo an already-sent request. Sara's private-local mode blocks this broker too.

Supply `method` (GET/POST/PUT/PATCH/DELETE/HEAD), an origin-form `path`, optional headers, optional JSON-object/array `body` text, and optional `replay`. Paths cannot contain queries, percent escapes, fragments or URLs. Configure no credentials in the destination. Only `127.0.0.1` is supported (not localhost, alternate loopback representations, IPv6, LAN or public hosts). The existing host socket broker holds all sockets; this plugin has no direct network API or workspace access.

Limits: 12 headers of 512 ASCII characters each; 4096 UTF-8 request-body bytes; 4096 response-header bytes; 8192 response-body bytes; 12288 total response bytes; two requests maximum. Broker connect deadline is 15 seconds per connection, followed by an at-most-2-second exchange deadline. One 20-second monotonic invocation budget includes both connects, responses and optional replay; no request is written after that budget expires, and a late-opened socket is closed without writing. No redirects, chunked transfer, compression, informational responses or streaming. Responses must contain empty or strictly decoded UTF-8 object/array JSON bodies. The actual body-byte bound also applies to close-delimited responses; HEAD/204 retain no-body semantics. Unsupported responses visibly refuse; they are not followed or silently truncated. A replay report compares actual raw JSON bodies and status, not a fabricated fixture response.

Output keeps method, path, public JSON data, response status, and only Content-Type/Accept/X-Public response headers. All other request headers are hidden. JSON keys containing authorization/cookie/token/secret/password/passwd/api-key/credential/session are redacted; their primitive values and hidden request-header values are also replaced wherever echoed in displayed strings. Response cookies/authorization values are collected before those headers are discarded. A collision between displayed JSON keys visibly refuses the whole result rather than silently overwriting public evidence. Do not put secrets in path or public headers. Redaction is a bounded sensitive-field/known-value policy, not detection of arbitrary secrets, encoded secrets or personal data; use synthetic data. Request/response data remains transient in plugin memory and the invocation result/card; the plugin does not write recordings. Host tool arguments/conversation persistence remains host policy, not a new credential store.
