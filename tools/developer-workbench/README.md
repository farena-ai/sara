# Developer Workbench S1

Dependency-free Node 24+ stdio MCP candidate, MIT, targeting Sara 2.68 contracts. Exact raw tools: `contract_diff`, `repo_map`; Sara names: `mcp_devbench_contract_diff`, `mcp_devbench_repo_map`. Offline, zero model/account calls. No executable/command/root/network tool. No installable store recipe: current installer cannot guarantee disabled + saved Ask before discovery. **Do not install as an automatic read-only tool.**

## Explicit staging and launch

Administrator code may call `stageSnapshot(reviewedQuiescentSource, freshOwnedServerHome)` from `repo-map.mjs`. It copies bounded non-sensitive regular files to a new `snapshot/` plus `snapshot-index.json`. This staging API is not remotely available over MCP; it is not a host-issued workspace grant. For Sara's actual stdio launcher, use its `<dataDir>/mcp/devbench` home, explicitly save server config `enabled:false`, and save **both exact tool names as Ask (or Off/never)** before enabling/discovery. Read settings back. Native Windows Node fallback is not an OS sandbox. Config command should be an explicit reviewed Node executable with only the absolute reviewed `server.mjs` path. `server.mjs` accepts no flags; its root is exactly its launch cwd. There is no environment-based root override.

For a fixture protocol session, launch Node with cwd equal to the freshly staged home. Send `initialize` (protocol `2025-06-18`), `notifications/initialized`, `tools/list`, `tools/call`; cancellation is `notifications/cancelled` with requestId, then `shutdown` and close stdin. The server limits requests to two in flight, 20 seconds each, 512 KiB input buffer. It supports cooperative file-I/O cancellation and checks cancellation before/after synchronous semantic analysis; it cannot interrupt a bounded synchronous JS turn in the middle. It spawns no children or listeners. No authority is derived from an annotation or MCP cancellation message.

`contract_diff` args: `{format:"openapi3", before:"contracts/base.json", after:"contracts/removed.json", locale?:"en"|"es"|"fr"|"de"|"pt-BR"|"it"}`. File paths must exist in the staged hash inventory. Output contains real file/hash/snapshot evidence and resolved JSON pointers. See API Contract Guard README for supported fail-closed OpenAPI subset and request/response variance. No YAML or external refs.

`repo_map` args: `{depth?:1..12,maxFiles?:1..256,locale?:...}`. Options only lower hard limits. Staging caps: 256 files, depth12, 256 KiB/file, 2 MiB aggregate, 1024 enumerated entries; map output is capped at 16 KiB. The mapper verifies every indexed file hash and rejects unindexed additions, symlinks/junctions, hardlinks, ancestor aliases, unsafe path names, UNC/device/ADS/traversal input and oversized data. Paths are deliberately portable and restrictive (ASCII relative segments, no hidden/config/secrets directories). No file bodies are returned. Sensitive filenames/config are omitted at staging, never hashed in output. Schema payload values are never emitted; structural identifiers themselves are evidence, with conservative sensitive/high-entropy identifier refusal. Arbitrary embedded secrets in innocuous source/identifier names cannot be reliably recognized: review staging inputs, never stage live private data.

Snapshots must be owner-reviewed, private and quiescent. Readonly attributes + lstat/fstat/hash rechecks detect accidental replacements; they do **not** establish an OS fence against a hostile concurrent writer controlling the home/index. Such shared writable roots are unsupported. H2 root grants and platform fencing remain host-owned; do not broaden cwd or mount an arbitrary repository to get a green test.

Native and MCP use byte-identical pure engine modules. Named properties override the effective additionalProperties fallback; omitted fallback is unconstrained. Both named/fallback transitions and fallback/fallback transitions obey request contravariance and response covariance. Optional typed additions to open request objects are not automatically compatible; closed-object optional request additions remain compatible. Implicit fallback evidence points to the actual containing object, not a nonexistent property. Six locales cover descriptions, summaries and errors; machine codes/protocol identifiers remain stable. Results are complete or explicitly refused, never silently truncated, below host channel limits.
